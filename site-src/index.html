How it is actually built

Every analytics product says it respects privacy. Here is what that means here, specifically enough that you can go and verify it.

The database enforces the separation

Every table holding your data has row-level security policies, and the application connects as a role those policies apply to. A bug in our code cannot show your data to someone else, because the database refuses independently.

The visitor hash changes daily

We truncate the address first, IPv4 to a /24 and IPv6 to a /48, then hash it with the browser, your domain and a salt that changes every day. The same visitor tomorrow is a different hash, and everyone on the same network is the same one.

No IP address is ever stored

Not truncated, not encrypted, not anywhere. There is no column for it, and none for the user agent either. Country comes from a database on our own server, so your visitors' addresses are never sent to a third party.

Nothing is written to the visitor's browser

No cookie, no localStorage, no fingerprint. The script sends an event and forgets. That is why no consent banner is needed, rather than a banner being technically avoidable.

Credentials are never stored usably

Passwords, session tokens and API tokens are all hashed. A copy of our database grants access to nothing. Sessions are Secure, HttpOnly and SameSite, and the dashboard loads no third-party scripts at all.

One server, in Sweden

Hosted with Bahnhof. Your data stays there, is not replicated to other regions, and is deleted automatically after 24 months. Our only other supplier is the one that sends the emails, in the Netherlands.
